## Постановка задачи

Хранить курсы валют к базовой (например, к BYN). Операции: задать/обновить курс, конвертировать сумму A→B через базу, список доступных валют.

## Содержание репозитория

| Файл | Содержание |
|------|------------|
| `structural.cpp` | Реализация в структурном стиле |
| `oop.cpp` | Реализация в ООП-стиле |
| `README.md` | Постановка задачи и описание проекта |

## Сборка и запуск

```bash
g++ -std=c++17 -o structural structural.cpp
./structural

g++ -std=c++17 -o oop oop.cpp
./oop
```

При запуске сначала автоматически выполняется демонстрационный сценарий, затем открывается меню для ручного ввода.

## Модель данных

Базовая валюта — **BYN**, её курс всегда равен 1. Для каждой валюты хранится курс к базовой: сколько BYN стоит одна единица этой валюты.

Конвертация A → B выполняется через базу в два шага:

```
сумма_в_базе  = сумма × курс_A
результат     = сумма_в_базе ÷ курс_B
```

## Реализованные операции

1. Задать или обновить курс валюты (с проверками: код не пустой, курс положительный, курс базовой валюты изменить нельзя).
2. Конвертировать сумму из одной валюты в другую через базовую.
3. Вывести список доступных валют с курсами.

Стартовый справочник: BYN 1.0, USD 3.25, EUR 3.51, PLN 0.82, RUB 0.035.

## Сравнение двух подходов

### Структурный стиль (`structural.cpp`)

- Данные — `struct CurrencyRate` и `vector<CurrencyRate>`, которые передаются в функции параметрами.
- Логика — свободные функции: `setRate`, `getRate`, `convert`, `findIndex`, `printCurrencies`.
- Ошибки возвращаются через `bool` + выходной параметр `string& error`.
- Данные открыты: любая функция может изменить поле структуры напрямую, корректность держится только на дисциплине вызовов.

### ООП-стиль (`oop.cpp`)

- `Currency` — валюта знает свой код и курс, сама проверяет корректность в конструкторе и сеттере, умеет переводить сумму в базу (`toBase`) и обратно (`fromBase`).
- `CurrencyConverter` — справочник с приватным `map<string, Currency>`, отвечает за хранение курсов и конвертацию.
- `ConverterApp` — отвечает только за диалог с пользователем, никаких расчётов не содержит.
- Ошибки — исключения `invalid_argument`, обрабатываются в одном месте.
- Состояние инкапсулировано: снаружи невозможно записать отрицательный курс, минуя проверку.

### Итог сравнения

| Критерий | Структурный | ООП |
|----------|-------------|-----|
| Где живёт проверка корректности | В каждой функции, работающей с данными | В классе-владельце данных |
| Доступ к состоянию | Прямой, поля открыты | Только через методы |
| Обработка ошибок | Код возврата + параметр ошибки | Исключения |
| Добавление новой сущности (например, истории конвертаций) | Новая структура + новый набор функций | Новый класс, остальные не меняются |

Оба варианта решают одну и ту же постановку и дают одинаковый результат. Единственное различие в выводе: в ООП-версии список валют отсортирован по алфавиту (`map` хранит ключи упорядоченно), в структурной — в порядке добавления.

## Пример работы

```
Доступные валюты (курс к BYN):
  BYN -> 1.0000 BYN
  USD -> 3.2500 BYN
  EUR -> 3.5100 BYN
  PLN -> 0.8200 BYN
  RUB -> 0.0350 BYN

1) Конвертация 100 USD в BYN:
   100 USD = 325.00 BYN
2) Конвертация 500 PLN в EUR (через базу):
   500 PLN = 116.81 EUR
3) Обновляем курс USD с 3.25 на 3.40:
   теперь 100 USD = 340.00 BYN
4) Добавляем новую валюту GBP по курсу 4.15:
   валюта добавлена
5) Проверка ошибок:
   отрицательный курс: Курс должен быть положительным
   неизвестная валюта: Валюта JPY не найдена
```
