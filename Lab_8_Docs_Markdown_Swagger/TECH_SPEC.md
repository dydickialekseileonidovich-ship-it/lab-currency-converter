# Техническая документация: Архитектура и ролевая модель

## 1. Архитектура решения
Система построена по сервисной REST-архитектуре:
- **Presentation Layer:** Веб-клиент (SPA) и OpenAPI Swagger UI для взаимодействия.
- **API Gateway / Backend:** Python/FastAPI сервис бизнес-логики.
- **Data Persistence:** Реляционная БД PostgreSQL для хранения структурированных заявок и логов аудита переходов.
- **Object Storage:** Хранилище MinIO/S3 для файлов справок и дипломов.

## 2. Ролевая модель (RBAC)
- **STUDENT (Студент):**
  - Разрешено: создание заявки (`POST /applications`), просмотр исключительно собственных заявок (`GET /applications?student_card={id}`), отмена черновика.
  - Запрещено: просмотр чужих заявок, изменение статуса рассмотрения.
- **DEANERY_STAFF (Сотрудник деканата):**
  - Разрешено: просмотр всех заявок факультета, смена статуса на `IN_REVIEW`, `NEEDS_INFO`, `APPROVED`, `REJECTED`, оставление служебного комментария.
- **ACCOUNTANT (Бухгалтерия):**
  - Разрешено: экспорт заявок в статусе `APPROVED` в виде платёжного реестра на выплату.

## 3. Матрица допустимых состояний заявки
```
[DRAFT] ---> [SUBMITTED] ---> [IN_REVIEW] ---> [APPROVED]
                                   |      \---> [REJECTED]
                                   v
                             [NEEDS_INFO] (возврат студенту)
```
